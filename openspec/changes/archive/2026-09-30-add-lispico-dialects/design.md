# Design

## Context

See proposal.md. Facts below come from go-lispico at `12e0990`. Slice 1 of three agreed for
Lispico support: dialects (this change), project contexts with library visibility, and
declaration catalogs. Ordered-prelude programs (zhk) and layered rules (Yagel) follow later.

## Goals / Non-Goals

Goals: the reader, forms, builtins and name resolution match go-lispico for both dialects.
Non-goals: per-project library selection, host symbols, catalogs, phases, arity checks against
Go builtins. Until contexts land, every file of a Lispico dialect sees the stdlib and all
same-dialect workspace definitions.

## Decisions

- **Standalone dialect files, no `extends`.** The stock dialects carry reader prefixes, forms
  and builtin lists go-lispico does not have; overriding them field by field is longer and
  easier to get wrong than two self-contained files.
- **Selection.** `language_ids = ["lispico-clojure"]` / `["lispico-cl"]`, no `extensions`, no
  modeline names. Open buffers pick up the client's language ID. Closed files are indexed by
  extension or association only (`src/workspace.rs:207-211`), so a project needs
  `files.associations` globs for cross-file results; README documents this.
- **Reader** (`core/reader.go:240-310`), both dialects: `;` line comments only, no block or
  datum comments, no character literals, commas as whitespace, prefixes `'` `` ` `` `~` `~@`
  `@`, keywords `:x`, `/` separator, case-sensitive. Clojure: `()` `[]` `{}`; `#` alone is
  invalid. CL: `()` only; `[` `]` `{` `}` are invalid; `#'` is a one-form prefix; `#(` opens a
  vector list.
- **Forms** (`core/dialect.go:23-46`, `cl/cl.go:204-227`). Clojure: the 21 kernel forms, `cond`
  with flat clauses. CL: kernel forms minus `set!` and `do`, plus `defun`, `setq`, `progn`,
  `funcall`, `function`. Definition forms: `def` (value), `defn`/`defun`/`defmacro` (function
  cell, params vector or list, `&` rest). Binding forms: `let`, `let*`, `loop` (vector pairs or
  list of pairs), `fn` (params). Existing let*-like visibility already matches go-lispico's
  sequential `let` (`core/eval.go:1902-1942`).
- **Builtins** are the stdlib names in `internal/inventory/registered.go` plus bootstrap macros
  `->`, `->>`, `as->`, `if-let`, `when-let` (`plugins/stdlib/bootstrap.go:17-38`). CL adds
  `car`, `cdr`, `null`, `append`, `length`; canonical names stay visible (`core/dialect.go:
  399-418`). The TOML header records the source revision.
- **Function cells.** `Binder` and `Def` gain a cell. With `function_cells = true`: function
  definitions bind the function cell, `def` and every local binder the value cell. An occurrence
  in call-head position, or as the argument of `function`/`#'`, looks only at function
  bindings; others only at value bindings. This mirrors `core/eval.go:852-858`, where a CL call
  head reads only the function cell. Dialects without the flag resolve as today.
- **No flet shape in Lispico.** Neither new dialect declares a flet-shape binding: go-lispico's
  binding forms are `let`, `let*`, `loop` and `fn` (Clojure) and the same (`cl/cl.go:204-227`
  maps no `flet`), and a case-insensitive search of the tree at `12e0990` finds no `flet` form.
  So the cell rule is scoped: a local binder binds the value cell in every dialect, including
  the `Flet` shape, which only the stock `common-lisp` and `clojure` dialects declare
  (`dialects/common-lisp.toml:127-129`, `dialects/clojure.toml:107`) and where it keeps today's
  single-namespace behavior because the flag is off there.
- **Cells are cross-file.** The workspace index keys definitions on the bare normalized name
  (`src/workspace.rs:52-54`, `def_keys` and `Index::by_def`), so a cell-aware occurrence is
  resolved against definitions in other files of the same dialect, not only against the current
  document. Two files, `(def n 1)` in one and `(defun n () 2)` in the other, must resolve the
  same way two forms in one file do; `src/workspace.rs` is part of the impact surface for that.
- **Invalid openers.** `reader.invalid` names the token openers the dialect rejects. The reader
  tests a declared opener before every other rule for that byte (`src/syntax/lexer.rs:80-137`):
  it is never classified `OPEN` or `CLOSE`, never starts a prefix, datum comment, block comment
  or sharp dispatch, and is read as one `Atom` token spanning exactly that byte, carrying a new
  `ErrorKind` variant whose code is `invalid-syntax` over the token's own range. One error per
  token, so `(f [x])` reports at `[` and at `]`. A dialect with an empty `reader.invalid` keeps
  today's classification for every byte: `common-lisp` (`dialects/common-lisp.toml:64`) and
  `clojure` (`dialects/clojure.toml:53`) get their rejection from `brackets` alone and are
  unchanged. This is a deliberate divergence from go-lispico, which fails the whole read with a
  hard `NewReadError` (`core/reader.go:254-259`); llsp keeps the tree lossless and the rest of the
  file parsing. Lists:
  - `lispico-clojure`: `["#"]`. go-lispico's Clojure spec sets neither `FunctionRef` nor
    `ReaderVector` (`clojure/clojure.go:18`), so bare `#` becomes `tokenHash` and dies in the
    parser's default branch (`core/reader.go:817-822`). Neither `#'` nor `#(` is a Clojure
    reader form, so the dialect sets `sharp_dispatch = false` and declares no `#` prefixes.
    The invalid-opener rule is the binding one: `#` is a one-byte `Atom` carrying one
    `invalid-syntax` error, no `#'` prefix token and no sharp dispatch are produced, and the
    bytes after it are read by the dialect's ordinary rules — `#'f` gives the invalid `#`, then
    the `'` prefix token, then the `Atom` `f`, and `#(1 2)` gives the invalid `#`, then the
    list `(1 2)`.
  - `lispico-cl`: `["[", "]", "{", "}"]`, the `NoBrackets` case (`cl/cl.go:206`). `FunctionRef`
    and `ReaderVector` are on (`cl/cl.go:207-208`), so `#'` (a declared prefix) and `#(`
    (sharp dispatch before `(`) stay valid and `#` is not an invalid opener there.

## Risks / Trade-offs

- [Builtin lists drift from go-lispico] → header revision; slice 3 replaces them with catalogs
  checked against the source.
- [Stdlib assumed present in every Lispico file] → true for the zhk and Yagel templates;
  contexts make it explicit in slice 2.
- [Closed files indexed under the stock dialect without associations] → documented; contexts
  in slice 2 select the dialect per file.
